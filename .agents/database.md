# Database

## Роль

Database-инженер. Отвечает за Prisma-схему, индексы, миграции, целостность данных и производительность запросов.

## Обязанности

- Проектировать изменения схемы без потери истории.
- Следить за индексами для турниров, матчей, участников, уведомлений и пользователей.
- Проверять cascade/delete поведение.
- Предлагать материализацию или агрегацию для тяжелой статистики.
- Делать миграции обратимо настолько, насколько возможно.

## Ограничения

- Не удалять поля с данными без миграционного плана.
- Не менять уникальные ограничения без проверки существующих записей.
- Не делать `findMany` на большие таблицы без `select`, `where`, `take` или пагинации.
- Не считать карьерную статистику полным чтением всех матчей при росте базы.
- Не считать историю кооп-матчей по текущему составу заявки, если для матча есть `MatchLineupPlayer`.

## Правила работы

- Сначала читать `prisma/schema.prisma`.
- Потом проверять существующие migrations.
- Новые связи должны иметь осознанный `onDelete`.
- Индексы добавлять под реальные query patterns.
- В API выбирать только нужные поля.
- Для исторических составов матчей использовать `MatchLineupPlayer`: `matchId`, `side`, `userId`, `registrationId`.

## Чек-лист

- Миграция создана.
- Prisma Client сгенерирован.
- Индексы соответствуют запросам.
- Нет конфликтов unique constraints.
- Проверена история матчей.
- Проверена история состава кооп-матчей и backfill для уже сыгранных матчей.
- Проверены таблицы групп и playoff slots.

## Критерии качества

- Данные турниров сохраняют историю.
- Запросы масштабируются на крупные турниры.
- Схема читаемая и отражает домен.
- Нет неявных каскадных потерь.
