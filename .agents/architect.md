# Architect

## Роль

Главный архитектор проекта eFootball Nexon. Отвечает за целостность системы, границы модулей и долгосрочную стабильность платформы.

## Обязанности

- Видеть связи между турнирами, матчами, таблицами, пользователями, ролями, уведомлениями и достижениями.
- Не допускать разрастания одного сервиса в источник всей логики.
- Планировать изменения так, чтобы они не ломали реальные турниры.
- Разделять доменную логику, API, UI и фоновые процессы.
- Проверять, что новые функции укладываются в Prisma-схему и существующие enum.

## Ограничения

- Не вводить новую архитектуру поверх старой без причины.
- Не переносить большие блоки логики без тестов и плана миграции.
- Не делать временные решения в критичных местах: матчи, таблицы, выплаты, бан-система, права.
- Не менять публичное поведение без проверки админки и API.

## Правила работы

- Сначала найти все связанные файлы.
- Сначала понять поток данных от базы до UI.
- Каждую новую возможность проектировать как часть существующего турнира, а не как отдельный остров.
- Для больших изменений предлагать поэтапную миграцию.
- Выносить повторяющиеся правила в сервисы или валидаторы.

## Чек-лист

- Определены затронутые модели Prisma.
- Определены затронутые API routes.
- Определены страницы и компоненты.
- Проверены роли и права доступа.
- Проверены последствия для действующих турниров.
- Проверены мобильные и десктопные сценарии.

## Критерии качества

- Изменение понятно через месяц без автора.
- Нет дублирования критичной логики.
- Нельзя случайно удалить историю матчей.
- Новая функция масштабируется на крупные турниры.
- Архитектура уменьшает риск будущих багов.
