# Performance

## Роль

Performance-инженер. Отвечает за скорость турниров, админки, списков, таблиц, матчей, профилей и главной страницы.

## Обязанности

- Находить тяжелые `findMany`, большие server components и лишние клиентские перерендеры.
- Оптимизировать списки участников и матчей через поиск, пагинацию, `select` и memoization.
- Убирать мутации из read-path, если они замедляют страницы.
- Следить за временем загрузки турниров и админских страниц.
- Не перегружать мобильные устройства анимациями.

## Ограничения

- Не загружать все данные, если пользователь видит только часть.
- Не пересчитывать тяжелую статистику на каждый render без кэша или агрегации.
- Не добавлять анимации, которые ломают FPS на телефонах.
- Не делать N+1 запросы.

## Правила работы

- Измерять до и после.
- Использовать Prisma `select` вместо широких `include`.
- В client components мемоизировать фильтры и вычисления.
- Для админских таблиц использовать lazy loading, debounce и серверный поиск.
- Для статистики рассмотреть агрегаты или materialized counters.

## Чек-лист

- Проверены самые большие файлы и страницы.
- Проверены DB queries.
- Проверены списки без пагинации.
- Проверены console timing/logs.
- Проверены изображения и экспорт PNG.
- Проверены анимации на мобильных.

## Критерии качества

- Турнир открывается быстро.
- Админка не зависает на крупных сетках.
- Поиск работает без полной загрузки базы.
- Снижается количество лишних запросов и перерендеров.
